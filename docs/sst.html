SST — heuristic dialectic search

What

SST is heuristic dialectic-MCTS search: diverge candidate patches, critique them honestly (CRITIQUE_FAILED is a kept verdict, never a fabricated APPROVE), synthesize survivors, and promote only through integrity + staleness + human gates. Model rollouts need caller-configured backends. (Source: components/sst/README.md + root README module table, 2026-10-18.)

Who it is for

Builders who want search with auditable failure: every candidate keeps its rationale, diff, checks, critic verdict, and evidence event links, and the event log is the source of truth.

  1. Diverge 3 candidates branch from the task root (dialectic temperatures 1.2 / 0.1 / 0.3 per pin record).
  2. Critique critic scores each branch; one fails honestly with CRITIQUE_FAILED (rank 0.5, kept visible).
  3. Alternatives survivors compared: rationale, diff, checks, evidence event links (UI Alternatives tab).
  4. Synthesize surviving branches merge into one unified candidate.
  5. Decide + promote human verdict recorded; promote passes integrity + snapshot + freshness gates.
  6. Reopen result rebuilds from the event log; unfinished runs report IncompleteSearchError.

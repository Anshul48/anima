3. **Integrate the mechanisms.** The root architect explains which problems are shared, which belong to local worlds, and where proposed abstractions conceal hard work. A separate note examines learned construction repertoires and cheap selection, including the limits of Jev.
4. **Review the synthesis independently.** A specialist reads the integrated draft for omitted user intent, contradictions, unsupported claims, scope drift and premature commitments. The root reconciles material findings and records what remains unresolved.
5. **Publish a proposed discussion map.** A short entry page links the synthesis, specialist dossiers, evidence limitations and bounded foraging prompts. It recommends an order for macro decisions and identifies questions suitable for focused project architects.

These are review steps, not a product roadmap or build sequence. The user can continue supplying material throughout; later inputs steer the same review.

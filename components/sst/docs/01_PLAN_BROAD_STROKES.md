## 1. The Clean Tripartite Architecture

The State Space Tree (SST) engine was initially embedded inside monolithic experimental frameworks. Under the production tripartite architecture, SST operates as an autonomous, decoupled search engine with a clear boundary of cognitive labor:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                 THE CLEAN REFACTORED TRIAD                             │
└────────────────────────────────────────────────────────────────────────────────────────┘

    1. TRACE (`trace/`)              2. STC (`stc/`)                  3. SST (`sst/`)
    ┌───────────────────────┐        ┌───────────────────────┐        ┌───────────────────────┐
    │ THE MEMORY SUBSTRATE  │        │ THE EXECUTION FACTORY │        │ THE SEARCH ENGINE     │
    │ • Hippocampal Spine   │        │ • Socratic Spec (TOC) │        │ • State Space Tree    │
    │ • Neocortex Holons    │        │ • Sub-25KB Bundles    │        │ • MCTS / UCT Policy   │
    │ • Byte-exact WAL      │        │ • Leased Worktrees    │        │ • Dialectic Rollouts  │
    │ • Negative Inhibitors │        │ • Substrate Gates     │        │   (Diverge/Refine)    │
    │ • Genome Store        │        │ • Blind Judiciary     │        │ • Colimit Synthesis   │
    │ • BM25 + Dense RRF    │        │ • Chaperone Runner    │        │ • $0 Sandbox Pruning  │
    └───────────────────────┘        └───────────────────────┘        └───────────────────────┘
```

- **`trace/` owns Truth & Memory**: "What has occurred, what invariants are proven, and what failure patterns must be avoided?"
- **`stc/` owns Physical Execution**: "How do we isolate, test, audit, and deterministically merge code changes into git repositories?"
- **`sst/` owns Cognitive Search**: "How do we efficiently explore high-dimensional code spaces and discover verified candidate solutions?"

## 2. The Five Core Pillars of SST

SST is structured around five foundational pillars designed to prevent the pitfalls of traditional linear chain-of-thought and brute-force LLM sampling:

### Pillar 1: Asymmetric Dialectic Search (Diverge, Refine, Critique, Synthesize)
Rather than relying on a single uniform prompt, search nodes are generated and evaluated through functional dialectic roles:
- **`DIVERGE`**: High-entropy divergent mutation generator ($T=1.20$, top-$p=0.95$). Explores non-obvious algorithms and novel structural designs.
- **`REFINE`**: Cold monotropic rigor and AST cleanup ($T=0.05$, top-$p=0.10$). Strips hallucinations, corrects imports, enforces typing, and produces exact unified diffs.
- **`CRITIQUE`**: Frontier value scoring ($T=0.20$, top-$p=0.30$). Audits architectural compliance and predicts candidate quality.
- **`SYNTHESIZE`**: Colimit dialectic merge that extracts and synthesizes complementary features from distinct passing candidate branches.
- **`HUMAN_DECISION`**: Escalation oracle triggered only when breaking changes, irreversible deletions, or profound ambiguities occur.

### Pillar 2: Zero-Cost Deterministic Sandbox Pruning
Every candidate patch generated by the engine is subjected to automated mechanical verification (AST syntax verification, linting, path containment, and automated test execution) before any frontier model evaluation is invoked:
- Branches that fail compilation, violate sandbox boundaries, or fail unit tests are pruned immediately.
- This results in **$0 in frontier LLM token costs** for defective, hallucinated, or broken branches.

### Pillar 3: Bounded Context Capsule Compilation
LLM performance degrades severely under unbounded context windows. SST enforces strict context boundaries via `ContextCapsuleCompiler`:
- Clips context to sub-25KB payloads containing only targeted module symbols, interfaces, and invariants.
- Embeds **Negative Inhibitors** retrieved from `trace/` (patterns previously proven to fail) to steer the search away from dead ends.
- Scrubs potential prompt injections and sensitive credential patterns before prompt synthesis.

### Pillar 4: Thread-Safe WAL SQLite Event Sourcing
Every state transition within the search space is immutably appended to a Write-Ahead Logging (WAL) SQLite event store:
- Trees can be fully reconstructed deterministically from event logs.
- Prevents database locking during concurrent branch explorations.
- Guarantees idempotent operations and prevents race conditions via optimistic concurrency leases.

### Pillar 5: Real-Time Cytoscape.js Streaming Visualizer
A built-in async HTTP streaming visualizer (`:8501`) provides immediate visibility into the search DAG:
- Live Server-Sent Events (SSE) stream state transitions in real time.
- Cytoscape.js rendering with Dagre hierarchical layout highlights winning paths, active frontiers, and pruned dead-ends.
- Exportable to standalone, zero-dependency HTML files for offline auditing.

## 3. Failure Modes and Defensive Mitigations

| Failure Mode | Risk Description | Architectural Mitigation |
| :--- | :--- | :--- |
| **Context Drift** | Multi-step agent chains accumulate subtle hallucinated interfaces. | MCTS tree branching isolates explorations; failed branches are abandoned without polluting sister branches. |
| **Combinatorial Explosion** | Unconstrained sampling leads to $O(b^d)$ branch explosion. | UCT exploration policy balances exploration and exploitation; zero-cost deterministic shears prune dead leaves immediately. |
| **Path Traversal Attacks** | Generated diffs attempt to write outside the sandbox (`../../etc/passwd`). | `CandidateCustodyManager` strictly resolves targets against root workspaces, rejecting absolute paths and relative directory traversals. |
| **Secret Exfiltration** | Prompts or diffs attempt to read or commit sensitive keys (`.env`, private keys). | Automated secret scrubbing scans patches and context capsules for API tokens, rejecting non-compliant proposals. |
| **Verifier Overriding** | High semantic scores might attempt to mask a broken test suite. | Rebuild invariant: a node with `FAIL_DETERMINISTIC` can **never** transition to `APPROVED_CORTEX`, regardless of subsequent evaluator scores. |
| **Budget Exhaustion** | Search loops runaway and consume unlimited LLM tokens. | `BudgetTracker` enforces strict ceilings on total iterations, wall-clock time, prompt tokens, and currency expenditure ($USD). |

## 4. Operational Invariants

1. **Deterministic Priority**: Deterministic gate results always supersede probabilistic model scores. A patch that fails automated tests is dead on arrival.
2. **Immutability of History**: Events in `SQLiteSSTStore` are strictly append-only. Once an event is written with a unique sequence number, it cannot be modified or deleted.
3. **Workspace Isolation**: Code proposals are evaluated exclusively within isolated temporary directory sandboxes or leased worktrees, preserving the primary repository in a clean state until explicit promotion.
4. **Human in the Loop**: When irreversible changes (such as file deletions or protocol breaking modifications) are detected, the engine pauses and requests a cryptographically audited human decision record.
